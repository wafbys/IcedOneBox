# 01 · 五条契约

> 五条契约不可动摇。核只关心这五件事。

## 1. 万物有 ID

任何实体、事件、消息，都有唯一标识。**ID 一旦生成，永不改变。**

实现：`onebox_id_generate()` / `onebox_core::generate_id()`，格式见 `10-ids.md`。

## 2. 一切皆事件

状态变化只通过事件记录。当前状态由事件推演。事件日志在，秩序就在。

实现要点：

- 事件只追加，不修改、不删除。
- `id`、`seq`、时间戳由核生成，调用方不得提供（见 `20-events.md`）。
- 快照：核提供快照的**存储与检索**，快照的**生成是外衣的责任**（见
  `30-snapshots.md`）。

## 3. 消息必经核

模块之间不直接通信。所有消息由核路由。

**核不解析内容，不判断对错，不修改消息。**

实现：`onebox_message_send()` / `onebox_message_subscribe()`（未实现）。
约定：核只做路由，消息内容对核是不透明字节/JSON。

## 4. 权限先声明

模块注册时声明权限。**核只做允许或拒绝。**

核不关心模块用权限干什么，只关心有没有越界。

实现：`onebox_permission_check()` / `onebox_permission_grant()` /
`onebox_permission_revoke()`（未实现）。

## 5. 模块有生命周期

注册、启动、心跳、崩溃、重启、注销。核统一管理。

**核不关心模块内部实现，只关心还在不在、活没活着。**

实现：`onebox_module_register()` / `onebox_module_unregister()` /
`onebox_module_heartbeat()` / `onebox_module_status()`（未实现）。

---

## 边界原则（由五条契约推出）

- 核不解析消息内容，不判断对错，不修改消息。
- 核不关心模块内部实现，只关心在不在、活没活。
- 核不知道外衣是什么，只处理注册、消息、事件、权限、生命周期。
- 凡超出以上范围的功能，都属于外衣或模块，不属于核。
