## 事件查询缺少「取最新 N 条」的反向接口

**现状（限制）**

`onebox_event_query` 只按 `seq` 升序返回，翻页靠 `since_seq` 单向前向推进，
没有「从末尾取最近 N 条」的能力。

**影响**

任何想「显示最近事件」的外衣都拿不到高效实现：

- WinUI 3 外衣（`shells/windows/OneBox.Shell.WinUI/MainWindow.xaml.cs`，
  常量 `QueryLimit`）用 `limit=1000` 查询后截取末尾 50 条绕过。
- 该绕过只在事件总数 ≤ 1000 时正确；超过 1000 条后，列表展示的将不是最新的
  事件，且没有任何提示。**这是权宜之计，不是正确实现。**

**候选方案（未决）**

未来若确有需要，考虑新增：

```c
onebox_rc onebox_event_query_recent(onebox_core *handle, uint32_t limit, char **out_json);
```

待定项：返回是否仍按 `seq` 升序？是否沿用现有查询信封？是否需要与
`event_type` / `source` 过滤组合？契约冻结前，核与所有外衣一律按
「正向查询 + 外衣自行截取」处理。

**触发条件**

真实使用中事件数接近或超过 1000，或某个外衣需要可靠的「最新视图」/分页时，
正式立项解决。
